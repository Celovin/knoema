# Holmes 1890s Historical Profile Research

## Overview

Holmes 1890s is a Tier 2 historical canonical profile for H. H. Holmes, born Herman Webster Mudgett (1861-1896). The profile is permitted by the handoff because the figure died before 1930 and appears in English-language criminology and crime-history canon. The research note must also correct myth. Holmes is often surrounded by exaggerated "murder castle" claims, while source-based histories emphasize fraud, insurance schemes, bigamy, deception, and a smaller set of confirmed murders than popular legend suggests. In the replay, the profile should focus on manipulation, spatial control, and commercial trust cues, not on architecture-as-weapon sensationalism. The profile must never provide operational fraud or harm instructions.

## Primary sources

Primary sources include Holmes' Own Story, published in 1895 under the name Herman W. Mudgett [C1]. It is useful as a period artifact but unreliable as self-serving narrative. Trial and legal-document links collected by law-school historical trial archives provide access points for the Holmes-Pitezel case [C2]. Contemporary newspapers and court reporting are primary when used as period evidence, but they also helped build legend. The profile should therefore treat primary sources as contested artifacts. It can encode deception, aliases, commercial fronts, and insurance-fraud context, but it should not repeat unsupported body counts or sensational room-by-room claims.

## Academic secondary sources

Selzer's biography is a source-based modern history that explicitly challenges legends and uses legal documents, letters, records, and newspapers [C3]. Franke's The Torture Doctor is an older historical secondary with an ISBN and a fact-oriented account of the Pitezel investigation [C4]. General serial homicide and offender-profiling literature supplies typology context [C5, C6]. Routine activity theory supplies convergence logic [C7]. Gangnam and Seoul CPTED sources support contemporary grid translation [C8, C9]. This mix is thinner in peer-reviewed case-specific literature than the Whitechapel profile, so the YAML should keep claims narrow and cite only broad behavior patterns: deception, financial motive, movement through commercial trust settings, and myth caution.

## Behavioral analysis

### Victim profile

The profile should not encode demographic victim rules. Historical accounts emphasize people drawn into business, insurance, employment, lodging, or trust relationships [C3, C4]. In the replay, this becomes "target with high trust cue and low verification support." It should be closer to a fraud-control profile than a street-convergence profile. The profile must not name victims or reproduce family details.

### Modus operandi

The safe MO translation is commercial manipulation: create a credible setting, exploit trust, delay verification, and relocate when scrutiny increases. The profile should not encode physical mechanisms, building traps, or disposal claims. Selzer's myth-correction emphasis is important here because the public version of Holmes often overstates architectural horror [C3]. The replay should show a simulated agent whose actions fail when verification guardians are present.

### Signature elements

No signature elements should be encoded. The profile should exclude trophy behavior, body-count claims, and "castle" mechanics. In teaching terms, the interesting point is how narrative inflation can distort criminological memory. The viewer panel should show "myth caution" and "source-limited" labels.

### Geographic behavior

The profile should use commercial anchors and route switching rather than alley hunting. It can have two or three anchor points: storefront, lodging-like cell, and transit edge. Rossmo's geographic concepts are useful for explaining anchor points [C6], but the profile is not a geographic profile of Holmes. It is a synthetic translation of commercial deception into a city grid.

### Temporal patterns

Temporal behavior should be tied to business-hour transitions and scrutiny. The agent can become less active when guardian density rises or when repeated failed interactions accumulate. It should not claim a historical hour-of-day pattern. The 7 p.m. replay is a modern demo stage, not a reconstruction.

### Victim-offender interaction dynamics

Interaction should be indirect and trust-based: offer arrangement, wait, disengage if verified, and shift route. No coercive dialogue or fraud script should be shown. This keeps the profile acceptable for academic and grant demos.

## Geographic profiling data

There is no encoded case-specific geographic profiling dataset. The profile uses anchor-point vocabulary from Rossmo [C6] and convergence language from Cohen and Felson [C7]. Synthetic parameters are: three anchors, high commercial-cell preference, low alley preference, and strong avoidance of verification guardians. The report should state that no external framework or historical case benchmark was run.

## Contemporary Seoul translation

Holmes' historical commercial and insurance-fraud context maps to a Gangnam commercial grid as a trust-and-commerce analogy, not as a crime comparison. Gangnam's modern commercial identity is supported by urban history literature [C8]. Seoul CPTED research supports visible guardianship and environmental cues [C9]. The replay can represent "verification guardian" as a blue marker and commercial cells as teal. The profile should demonstrate that social and institutional guardianship disrupts deception.

## Ethical considerations

Holmes is surrounded by popular myth. The profile must not amplify unsupported numbers, torture architecture, or lurid details. It should teach source criticism: self-authored prison narratives, newspapers, and later books disagree. Because the figure died in 1896, the Tier 2 rule permits a named historical profile, but the repository should still avoid sensational detail and victim names. If future users want more case depth, they should add primary-source citations and keep operational details out.

Implementation should lean toward economic-crime abstraction rather than physical horror. The YAML should include trust cue, commercial front, verification delay, and scrutiny avoidance. It should exclude building mechanisms, body-count claims, and room descriptions. This makes the profile useful in the same viewer as the fraud archetype while still preserving its historical identity. The profile panel can say "myth-corrected commercial deception profile" to signal the design choice.

The source base is uneven. Holmes left a self-serving text; newspapers amplified the case; later histories disagree over what was confirmed. The profile must therefore avoid any claim that depends on a single sensational source. Where Selzer or Franke is used, the YAML should cite them for broad historical framing, not for a procedural rule. Where general serial-homicide literature is used, it should be clear that the source supports typology caution rather than Holmes-specific facts.

The Seoul translation should be modest. A Chicago World's Fair-era commercial and insurance context does not map directly onto a 2026 Seoul grid. In the replay, commercial cells stand for transactional trust, main roads stand for movement and scrutiny, and guardian cells stand for verification support. The historical profile is a teaching overlay about deception under institutional gaps, not a claim about any modern district. It should be safe to show to non-technical stakeholders because it contains no operational content.

Finally, the profile should help demonstrate Knoema memory rather than true-crime spectacle. The most useful panel rows are memory states such as "verification request observed" or "commercial trust cue failed." These rows show how a simulated agent's memory changes when social guardianship appears. That is the product-relevant lesson.

The profile should also be excluded from any UI path that suggests present-day risk scoring. It is a historical teaching overlay, not a model of merchants, landlords, doctors, or entrepreneurs. The viewer should present it with an ethics acknowledgement and a myth-correction note. If a future source contradicts one of the broad claims, the YAML should be updated before the profile is used again.

The safer product lesson is verification, not fascination with the historical legend. The overlay should demonstrate how memory traces and guardrails can interrupt synthetic deception, while the source panel reminds viewers that popular Holmes narratives often outrun the record. This keeps the profile useful for Knoema's replay capabilities without turning the demo into crime entertainment.

If the profile feels sensational, the implementation has failed. It should feel like a source-critical prevention model, with commercial trust, verification, and auditability as its visible variables. That tone also makes it easier to present to faculty who may be skeptical of true-crime material in a technical demo.

The final profile should prefer conservative omissions over dramatic uncertain claims.

That rule is non-negotiable.
